# Restored Custom Tab OAuth

1. Provider buttons use an origin-restricted Android message bridge when available.
   Normal browsers keep their regular Auth.js login. Older app versions can still intercept
   provider authorization navigations.
2. Android retains a random verifier in an activity ViewModel, and opens
   `/android-signin?provider=...&code_challenge=...` in a standard Custom Tab.
3. Auth.js starts and finishes provider login entirely in Chrome using existing callbacks.
4. `/api/android-callback` validates the browser session, issues a 60-second one-time code
   bound to the challenge, and returns a package-targeted `notizen://auth` intent.
   The page attempts to return automatically and offers Open Notizen if Chrome blocks it.
5. Android redeems the code at `/api/exchange`. Validation and deletion are atomic;
   wrong verifiers cannot consume a valid code. The existing `android_auth_codes` table is reused.
6. Android installs the complete session-cookie set, awaits completion, flushes cookies,
   then loads notes. Session expiry is not extended beyond the original JWT expiry.

No Auth Tab API is used. No new provider redirect registration or signing-fingerprint
association is needed for this Custom Tab handoff. Existing assetlinks.json is retained
because it is harmless and may be used for other links.

Google and Discord remain enabled as configured. Clever and ClassLink are supported but require
website OAuth client configuration. See the [website setup guide](https://github.com/sashalukin/Notizen-website/blob/fix/restore-custom-tabs/docs/school-sso.md).
The callback wire format (`code` UUID + `code_verifier`) remains compatible with old clients.

The pending verifier survives activity recreation, not process death. If Android kills the
process during login, the user must start again. Cancellation never clears existing sessions.

Verification: automated provider simulation, PostgreSQL handoff/expiry/replay/concurrency
checks, Android JVM tests/lint/compilation, and browser routing checks. Real provider login
on a device must also be checked. No APK is generated by the verification commands.
